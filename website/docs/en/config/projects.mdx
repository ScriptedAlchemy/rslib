# projects

- **Type:** `string[]`
- **Default:** `undefined`

Use `projects` to enable workspace orchestration mode in Rslib.  
When this option is set, Rslib treats the current config as a workspace config and resolves child Rslib projects from the provided paths or glob patterns.

## Basic usage

```ts title="rslib.config.ts"
import { defineConfig } from '@rslib/core';

export default defineConfig({
  projects: ['packages/*'],
});
```

Then you can run commands in the workspace root:

```bash
rslib build
rslib inspect
```

## Supported project entries

Each item in `projects` can be:

- A directory path (Rslib will load the config inside that directory)
- A config file path
- A glob pattern (for matching multiple directories or config files)

Each entry must be a non-empty string.  
If `projects` contains non-string values or only empty entries, Rslib throws an explicit configuration error.
When possible, the error message also includes the related config file path to help locate the invalid entry.

If all project entries resolve to no child projects (for example, an unmatched glob), Rslib throws a `No child projects found from workspace projects` error.
The error includes the unmatched entry patterns and, when possible, the related config file path.
The reported entry patterns are normalized by trimming surrounding whitespace.
If duplicated patterns are provided, the diagnostic output collapses them to normalized unique entries while preserving first-occurrence order.

The same validation rules apply to nested workspace configs as well.
If a nested child config is invalid, the error message includes that child config path.

For example:

```ts title="rslib.config.ts"
export default {
  projects: ['packages/*', 'apps/**/rslib.config.ts', './examples/shared-lib'],
};
```

You can combine this with the top-level `root` option.  
When `root` is set in a workspace config, project entries are resolved relative to that root.

## Nested workspace configs

A child project can itself provide a workspace config with `projects`. Rslib will resolve these nested projects recursively.

## Dependency ordering

In workspace mode, `rslib build` builds projects in dependency order.

Rslib infers local dependencies from each child project's `package.json` and sorts projects topologically before building.  
If a circular dependency is detected, Rslib throws an error.
For independent projects without dependency relationships, Rslib uses a deterministic order.

## Project filtering

Use [--project](/guide/basic/cli#common-flags) to run commands for specific workspace projects:

```bash
rslib build --project @scope/pkg-a
rslib inspect --project @scope/pkg-*
```

`--project` supports wildcard and negation patterns.
Each `--project` value must be a non-empty string.
For negation patterns, the value after `!` must also be non-empty (for example, `!@scope/legacy` is valid, while `!` is invalid).
Rslib trims surrounding whitespace for each `--project` value before matching.

When filtering projects:

- `rslib build --project ...` automatically includes local workspace dependencies of selected projects, then builds in dependency order.
- `rslib inspect --project ...` only inspects the selected projects.

So if a selected project depends on another local project, that dependency will still be built even if it is excluded by a negation pattern.
If filters match no projects, Rslib reports the filter miss and prints available workspace project names to help you pick valid values.
The available workspace project names in this diagnostic are listed in deterministic sorted order.
The filter-miss error also includes normalized `--project` filters (trimmed and normalized for negation patterns) so you can quickly identify which pattern combination excluded all projects.
Repeated `--project` patterns are collapsed to normalized unique entries in first-occurrence order in the filter-miss diagnostics.

## Notes

- `projects` and `lib` cannot be used in the same config file.
- Setting `lib` to `undefined` is treated the same as omitting `lib` in workspace mode.
- Each resolved workspace project name must be unique. Rslib uses `package.json` `name` as project identity when available, otherwise it falls back to the project directory name.
- In workspace mode, currently supported commands are:
  - `rslib build`
  - `rslib inspect`
- `rslib build --watch` and `rslib mf-dev` are not supported in workspace mode yet.
